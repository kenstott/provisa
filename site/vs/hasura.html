Provisa / Provisa and Hasura

Where the v2 idea kept going.

Hasura DDN is centred on instant, per-role GraphQL APIs over your own databases — metadata-driven, with a connector-per-source model for federation. Provisa shares that core idea and extends it: more languages, more protocols, a federation engine with real join statistics, and governance that holds identically on every entry point. Bring your Hasura v2 metadata — the converter reads it and writes a Provisa config in one command.

One command

# Read a Hasura v2 metadata directory, write a Provisa config
python -m provisa.hasura_v2 ./hasura/metadata -o provisa.yaml

# Validate without writing, map schemas onto domains, override connections
python -m provisa.hasura_v2 ./hasura/metadata --dry-run
python -m provisa.hasura_v2 ./hasura/metadata --domain-map public=sales billing=finance

Sources, tables, row permissions, relationships, remote schemas, actions and event triggers all convert. Roles and rate limits come across as Provisa roles. Anything that doesn't map cleanly becomes a warning so you have a list to work through, not a silent gap.

Use them together

If you already run Hasura DDN for your application's GraphQL API, Provisa can provide the governed semantic layer underneath it — or alongside it for the queries that go beyond what the connector model covers. Your Hasura permissions and connectors stay in place.

Where they complement each other most directly: Hasura handles the immediate app API with its DDN supergraph; Provisa handles the SQL analytics layer, the graph traversals, and the MCP connection that agents use. Both draw from the same underlying databases.

What you keep coming from Hasura v2

A per-role API over your database, generated from metadata, with permissions enforced at query time. Per-role schemas, field-level visibility, cursor pagination, aggregates, Apollo Automatic Persisted Queries — all of it carries across. No new modeling universe to learn, no rewrite as the price of admission.

If you only need Hasura DDN

Your application speaks GraphQL. Your data lives in relational databases you own. You want a metadata-driven connector-per-source model with lambda functions for custom logic, and PromptQL handles the AI access your team needs. Hasura DDN covers that well on its own.

If you only need Provisa

Your consumers are not only GraphQL clients. You need Cypher, SQL, or pgwire on the same governed model. Cross-source analytics runs at a scale where join statistics and spill-to-disk matter. You need to run entirely off-network without an enterprise license gating the self-hosted path. Or you're migrating from Hasura v2 and want a single conversion rather than a DDN supergraph rebuild.
