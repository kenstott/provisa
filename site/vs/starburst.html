Provisa / Provisa and Starburst

Two different centres.

Starburst is centred on SQL analytics in a managed Trino lakehouse — governance, data products, and agent access all build outward from that engine. Provisa is centred on a governed model that works over the engine you choose, Starburst included. Which centre matters is the question worth asking first.

Use them together

Register Starburst as the federation engine in Provisa. Starburst keeps doing what it does well: SQL federation at scale, Gravity ABAC, and Galaxy data products. Provisa adds GraphQL, Cypher and SPARQL over the same data, governed transactional writes routed past the engine, and consistent policy on every protocol — including MCP agents. Starburst's data products and Gravity stay exactly where they are.

The engine keeps doing what it is good at. Your semantics and policy stop living inside it, which is what makes it replaceable later if you ever need that.

If you only need Starburst

Your consumers are SQL and BI tools. You want one vendor's managed Trino platform with governance (Gravity), curated data products, and agent access over SQL. You are committed to Trino as the engine. Starburst covers that well on its own.

If you only need Provisa

You need more than SQL — GraphQL, Cypher, SPARQL, or transactional writes. Governance must hold identically on every protocol, agents included. You want to connect the model to your existing catalog and lineage tools rather than running everything inside one engine vendor. Or you need to run from a single wheel, on a laptop, without a cluster.
