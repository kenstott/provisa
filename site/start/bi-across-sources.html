Provisa / BI across sources

Now the business wants it in Tableau, and the warehouse project is a year away.

Connect the BI tool to Provisa over JDBC or the Postgres wire protocol and join across every source, with no pipeline into a warehouse first and no copy in the middle. Each analyst sees the governed view of their role.

Connect your data, query with SQL from Tableau, in five minutes

1. Install and start Provisa

Download the installer for your machine from the download section and run it. The first launch finishes a one-time setup with no internet needed. Then start the services and open the UI.

provisa start   # every service, on your machine
provisa open    # the UI, in your browser

2. Connect the sources

In the UI, open Sources and add Postgres, Snowflake and a Google Sheet. Provisa reads each source's catalog; pick the tables to register. Nothing is copied: queries go to the data where it lives.

3. Check the join in SQL

Provisa speaks the Postgres wire protocol on port 5439. The user name selects the role:

psql -h localhost -p 5439 -U analyst

SELECT r.region, SUM(o.total) AS revenue, t.target
FROM orders o
JOIN regions r ON r.id = o.region_id
JOIN targets t ON t.region = r.region
GROUP BY r.region, t.target;

4. Connect Tableau

Add the Provisa JDBC driver (provisa-jdbc.jar) to Tableau's driver folder and connect with Other Databases (JDBC), or use Tableau's PostgreSQL connector against port 5439. Sign in with your Provisa user; the server assigns your role.

jdbc:provisa://localhost:8815

5. Build the dashboard

The tables appear by domain, with only the columns your role reads. Joins Tableau writes across sources run in Provisa.

What stays true

  • Row rules and masks apply to every query the BI tool sends.
  • The catalog a BI tool browses is scoped to the role.
  • A slow source can be replicated by Provisa without changing the dashboard.
