Provisa / Data provisioning

Now three other teams need it, and each one wants its own pipeline.

The consuming team writes SQL and gets it back fast: Arrow over Flight, typed gRPC, and, past a row threshold, a presigned URL for a multi-GB result instead of a timed-out HTTP response. Kafka carries the change notifications, so they pull the delta rather than the snapshot.

Connect your data, deliver it to every team, in five minutes

1. Install and start Provisa

Download the installer for your machine from the download section and run it. The first launch finishes a one-time setup with no internet needed. Then start the services and open the UI.

provisa start   # every service, on your machine
provisa open    # the UI, in your browser

2. Connect the sources

In the UI, open Sources and add the systems the teams read. Provisa reads each source's catalog; pick the tables to register. Nothing is copied: queries go to the data where it lives.

3. Give each team a role

One role per consuming team, granted the domains and columns its contract covers. Each team's view is enforced by Provisa, not by a pipeline built for it.

4. Deliver a large result as a file

Ask for the result to be delivered: Provisa writes it to the results store and answers with where it is.

curl -X POST http://localhost:8001/data/sql \
  -H "Content-Type: application/json" \
  -H "X-Provisa-Role: finance" \
  -H "X-Provisa-Redirect: true" \
  -d '{"sql": "SELECT * FROM transactions"}'

5. Stream the changes

Subscribe to a table and send its changes to a Kafka topic, so a team reads what changed since its last pull.

What stays true

  • Every team's access is the same governed model, not a copy per team.
  • The operator's limits protect each source from a team's load.
  • Each delivery is in the request record, with the role it ran as.
