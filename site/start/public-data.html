Provisa / Public data

Now someone wants it joined to public data, and that means another ETL job.

Join your database by county to NOAA weather, by CVE to CISA's exploited-vulnerability catalog, by LEI to Wikidata's ownership graph, or by NDC to FDA recalls, with no ETL and no pipeline. Every join is governed the same way as any other.

Connect your data, join it to public data, in five minutes

1. Install and start Provisa

Download the installer for your machine from the download section and run it. The first launch finishes a one-time setup with no internet needed. Then start the services and open the UI.

provisa start   # every service, on your machine
provisa open    # the UI, in your browser

2. Connect the sources

In the UI, open Sources and add your database and a public source (a REST API, a SPARQL endpoint or a published file). Provisa reads each source's catalog; pick the tables to register. Nothing is copied: queries go to the data where it lives.

3. Relate the public data to yours

Relate your table to the public one on the shared key: county, CVE, LEI or NDC. The relationship is a governed join like any other.

4. Query across both

Over any interface; in SQL:

SELECT a.hostname, k.cve_id, k.due_date
FROM assets a
JOIN installed_software s ON s.asset_id = a.id
JOIN known_exploited k ON k.cve_id = s.cve_id
WHERE k.due_date < CURRENT_DATE;

5. Or start from a demo

The public-data demos come ready to run, each with a guided tour.

What stays true

  • A public source is registered once and governed like your own data.
  • Freshness is declared on the source, so a slow public API is cached or replicated for you.
  • Results that join public data carry the same row rules and masks as any other.
