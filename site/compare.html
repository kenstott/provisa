Where Provisa fits

Most data tools are bound to one engine, or sit beside your systems after the data already exists. That is the root of fragmented, hand-integrated architectures: each tool describes or governs a slice of the picture, and nothing keeps the slices in sync. Provisa is a data kernel — a compiler and runtime for your data control plane. You declare the model once. APIs, governance, catalog entries and semantic definitions are generated from that declaration. Nothing exists outside the model to drift.

The landscape

CategoryExamplesWhat it does with the mess
Catalogs and governance Atlan, Collibra, Alation, DataHub Describes it after the fact. Helps you see it. Does not stop it forming.
Engines and lakehouses Starburst, Dremio, Databricks, Snowflake, Microsoft Fabric Centralises it in one platform. Each offers some reach beyond itself (federated queries, external tables, mirroring or shortcuts) and its own governance tools, and the quality of both varies. All of them are incomplete in one way or another, all of them want your data moved in, and most leave you on their cloud. Each feature binds you further to that platform.
Data virtualisation Denodo Queries sources live through virtual SQL views. The virtualisation platform is the engine.
Semantic layers dbt Semantic Layer, Cube, AtScale Defines metrics once for analytics, typically over one SQL warehouse.
API layers Hasura, PostgREST GraphQL APIs over one or more databases, built for transactional workloads. Has its own governance, which is hard to integrate with governance spread across other systems. Works well for a focused transactional environment; other languages and workloads need something else alongside it.
Provisa Stops it forming. Declares the model once — sources, governance, semantics, APIs — and keeps the others in sync, or runs alone.

Detailed comparisons

Catalogs and governance

Atlan, Collibra, Alation, DataHub. Provisa publishes to your catalog so it shows what is actually enforced.

Engines and lakehouses

Starburst, Dremio, Databricks, Snowflake, Microsoft Fabric. Keep the one you have and register it as an engine in Provisa, alongside others or embedded DuckDB, so no single platform becomes the place your data has to live.

Data virtualisation

Denodo. Same premise — governed access over distributed data without duplicating it. Different engine story.

API layers

Hasura, PostgREST. Provisa adds SQL, Cypher, and more protocols over one governed model, across all your sources.

Semantic layers

dbt Semantic Layer, Cube, AtScale. Provisa imports models from these tools through Apache Ossie — the open standard for describing what metrics mean. Each import is a proposal you review before it registers. You can use Provisa alongside your semantic layer, or let the model replace it over time.
